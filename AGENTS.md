# AGENTS.md — branchdam-agent

This file is the single source of truth for this repo's workflow rules and
load-bearing invariants — the ones every agent needs before touching
anything, regardless of which CLI you are. `CLAUDE.md` is a one-line
`@AGENTS.md` import, so every CLI (Claude Code, Codex, opencode, agy) reads
this file, natively or via that import. See [`CONTRIBUTING.md`](CONTRIBUTING.md)
for the contributor workflow and [`docs/`](docs) for deeper architecture detail.

Workstation companion agent for branchDAM. Handles SD card ingestion, dual-copy
verified storage writes, offline queueing, and catalog sync. Go binary
(cross-platform: Linux, Windows, macOS) with system tray UI.

## Commands

```sh
# Pre-PR Gates & Testing
make check           # build + vet + test (race detector + coverage)
make lint            # pre-commit run --all-files (golangci-lint + vet + detect-secrets)

# Cross-compilation Builds
make build-windows   # Builds dist/branchdam-agent.exe and dist/branchdam-agent-tray.exe
make build-darwin    # Build-only check for darwin/arm64
make build-darwin-app# Assembles macOS .app bundle via tools/mkbundle
```

## Package Responsibilities

| `internal/branchdam` | REST client for branchDAM `/api/v1/agent/*` contract (`hello`, `handshake`, `events`, `rebase`, `node-status`, `check-content`, `upload` (on its own HTTP client with no total timeout), `telemetry` (posted by the tray's own 15-minute timer via `Runner.TriggerTelemetry`, skipped while paused or config-incomplete)) |
| `internal/ingest` | DualWrite (streaming multi-writer), cache-defeating Verify, EXIF/SRT metadata extraction, naming engine |
| `internal/queue` | Local SQLite queue (`queue.db`) persisting ingest records and retry states for offline field operation |
| `internal/tray` | Menu bar / system tray companion (Windows/macOS) with loopback HTTP status server (`127.0.0.1:38080`, `config.DefaultStatusAddr`; rejects any `Host` that isn't a loopback name/IP on its port, against DNS rebinding) |
| `internal/selfupdate` | Checksum-validated self-update (`go-selfupdate`) with multi-target apply that is all-or-nothing for any failure the process survives (a failed target restores the ones already swapped; the rollback sidecar is written only after every target swaps; a crash mid-apply is not covered -- see `docs/platform-support.md`) and instant rollback |
| `internal/luminar` | Read-only Luminar Neo catalog parser (schema verified against `db_version 155`) generating Tier-2 lineage edges from filename-inferred pairing -- see `docs/luminar-catalog.md` |
| `internal/resolvehook` | Detects and installs DaVinci Resolve's render hook into its `Scripts/Utility` folder (`CandidateDirs`/`Detect`/`Install`, atomic temp-then-rename write) |
| `internal/nodeindex` | File path to `nodeUuid` lookup resolver |
| `internal/hashing` | Ported xxHash64 `FastHash`, `StreamingFastHasher`, BLAKE3 `FullHash`, and `PerceptualHash` |
| `internal/config` | YAML config loader with environment expansion and surgical `yaml.Node` atomic patcher |
| `internal/exiftool` | Pooled `exiftool -stay_open` subprocess manager (`Pool`), shared by `internal/ingest`'s EXIF extraction and `internal/phash`'s RAW preview fallback |

## Key Invariants

1. **Streaming Dual-Write (`DualWrite`)**: Ingestion reads the camera card once, streaming bytes to both the local edit SSD and NAS archive simultaneously while computing xxHash64 and BLAKE3-256 in-flight. Never re-reads the card to compute hashes. Upload mode (`ingest.uploadStream`, `internal/ingest/upload.go`) holds to the same rule: the card is read once into a verified local temp copy, and the upload streams that copy with its BLAKE3 in `X-Blake3-Hash`.
2. **Cache-Defeating Verification (`Verify`)**: Flushes (`fsync`), closes, and re-opens files unbuffered (`O_DIRECT` on Linux, `F_NOCACHE` on macOS, `FILE_FLAG_NO_BUFFERING` on Windows). Falls back to the buffered floor once at open time, never mid-stream, and only on the errors that mean "unbuffered unsupported here": `EINVAL`/`EOPNOTSUPP` (Linux `O_DIRECT`, e.g. tmpfs), `ENOTSUP` (macOS `fcntl`), `ERROR_INVALID_PARAMETER`/`ERROR_NOT_SUPPORTED`/`ERROR_INVALID_FUNCTION` (Windows `CreateFile`, `windowsUnbufferedUnsupported`); any other open error is surfaced. macOS `F_NOCACHE` is advisory -- already-cached pages can still be served -- so a macOS `unbuffered` verify is not a guaranteed cache bypass (`verify_darwin.go`, docs/platform-support.md).
3. **Offline Queue Safety (`queue.db`)**: Ingest intent is persisted in local SQLite before network calls -- offline ingest always, online ingest whenever `offline.queueDbPath` is set (an `origin = ONLINE` row inserted before the `EVENT_NODE_CREATED` POST; a POST that isn't accepted leaves it for `Drain` to retry, and the file reports `Queued`, not failed). Upload mode (`ingest.uploadStream`) writes no queue row -- the server registers the node within the upload request itself -- and a metered-deferred upload is not queued yet (no upload-pending stage; see `docs/offline-queue.md`). Online ingest maps the archive path (`ToContainerPath`) before `DualWrite`, and a re-run that finds identical copies at both destinations skips only on evidence of registration (a claiming queue row, or a live node with that content per `check-content`), otherwise it registers them -- never a silent skip, never a bypass of `requireUnbuffered`. `ctx` cancellation is checked per file and per read buffer (`WithContext`). Offline drain enforces `MinRebaseDwell` (4s) to guarantee server-side event consumption before emitting `/rebase`. `queue.Open` sets its pragmas (busy_timeout, WAL, `synchronous=FULL`, foreign_keys) through the DSN's `_pragma` list so every pooled connection gets them, and escapes the path as a `file:` URI. `CopyToArchive` gives the archive copy the local copy's mtime and fsyncs the directory after the rename; an edited local copy, a conflicting archive file, or two consecutive read-back mismatches end the row in terminal `archive_copy FAILED` (an existing archive file of exactly the local copy's size that reads back wrong -- typically the agent's own copy, left after a read-back error -- counts as a read-back mismatch, not a conflict, and is never removed). Drain's daily row GC deletes only rows that finished successfully, are older than 90 days, and whose local copy is gone, so pending and FAILED rows and rows prune still needs are never collected. See `docs/offline-queue.md`.
4. **Path Translation (`ToContainerPath`)**: Agent payload paths are container-absolute, translated client-side via `pathMappings` (longest-prefix match) before dispatch.
5. **Double-Encoded Event Envelopes**: `/api/v1/agent/events` payload is a double-encoded JSON string; inner `evidenceJson` in `EVENT_EDGE_ATTACHED` is a raw JSON object.
6. **Surgical Config Patching (`patch.go`)**: Config writes mutate raw `yaml.Node` ASTs and write atomically (0600, temp file fsynced before the rename, directory fsynced after), preserving comments and unexpanded `${VAR}` placeholders. `Patch` calls are serialised in-process (`patchMu`), and a symlinked `config.yaml` has its target replaced, never the link.
7. **Client-Side Edge Validation**: `ValidateEdgeAttached` strictly enforces confidence `[0.50, 1.00]`, allowed relationship types, and rejects agent-supplied `reviewState` before POSTing.
8. **Prune Safety Checks**: `prune` only operates on offline-ingested (`origin = OFFLINE`) `queue.db` media rows whose archive copy is `DONE`, and only deletes one when `POST /api/v1/agent/node-status` reports the node found, live (`ACTIVE`/`HIDDEN`), `TIER3_MASTER_ARCHIVE` and `verified`, **and** the `fullHash` it returns equals (case-insensitively) the BLAKE3 hash `queue.db` recorded for that file at ingest -- `verified` alone only means the server holds *a* 64-hex hash. The equality proves only that the server's record still matches the agent's ledger (for offline rows the server's `full_hash` is the one the agent sent); that the archived bytes match rests on `verified`, which on branchDAM with `full_hash` provenance (#505) requires a server-computed hash. A server that omits `fullHash` (older than branchDAM #538) prunes nothing: those files are kept and counted as `no-server-hash`, a mismatch as `hash-mismatch`, a row with no hash recorded at ingest as `no-local-hash`, each with a `[SKIP]` line and a pass-level `slog.Warn` (the tray discards per-file output). Re-verifies local containment and disk mtime/size before deletion. (`internal/prune/prune.go` `Pass`)
9. **Tray Gate Serialization**: `Runner.TriggerIngest` serializes concurrent card insertions and manual clicks behind `gate`. Reconfiguration rebuilds components via `Runner.Reconfigure`, which never waits on `gate`: while an ingest holds it, the newest call is recorded and applied as soon as the gate frees (`ReconfigurePending` / `SettingsView.ApplyPending`), never swapping the engine under a card mid-copy; the replaced engine is `Close`d (its exiftool pool). Settings saves are serialised end to end by `configSettings.saveMu`. The Wails window's actions are thin drivers over the same `Runner` (`internal/tray/statusapi.go`): "Ingest now"/"Import from folder…" (`POST /api/actions/ingest-start`, 202 at once) run every volume through `TriggerIngest` (manual: no `IngestGate`, never auto-ejects), "Drain now"/"Prune now" call `TriggerDrain`/`TriggerPrune` under `drainPruneClickTimeout`, and "Roll back" (`StartRollback`) takes `TryLockIdle` then `applyMu`, like `StartApply`. `Runner.CancelIngest` stops an ingest only at a file boundary (`ingest.WithFileBoundaryCancel`: the in-flight file finishes copy, verify and registration/queue row; the summary is `Canceled`, never `OK()`, so no eject) and takes no gate. Failed queue rows are re-queued with `queue.Store.ResetFailedNode`/`ResetFailed` -- no lock needed, a drain never selects a FAILED row.
10. **`internal/naming.Stem` Is a Locked Port**: byte-for-byte port of branchDAM's own `naming.Stem` (conformance verified against that repo's own golden test table). Its role-suffix pattern must never gain Luminar-specific suffixes — `internal/luminar/derive.go`'s own local `stem` helper exists so `PairDerivatives` doesn't need to touch it. See `docs/luminar-catalog.md`.
11. **LastHandshakeAt Carry-Forward (in-session)**: A failed drain pass must not erase the prior successful `LastHandshakeAt` -- the carry-forward in `TriggerDrain` keys off `r.lastDrain != nil && !r.lastDrain.LastHandshakeAt.IsZero()` (PR #148, Hermes review). Initial failures (no prior successful stamp) stay at the zero sentinel; the Wails window's `fmtTime` (`cmd/branchdam-agent-ui/frontend/dist/app.js`) returns `null` for a zero-value timestamp (`d.getFullYear() <= 1`), and `renderServer`'s `if (lastHandshake) rows.push(...)` guard suppresses the "Last successful handshake" row in that case -- the same suppression the tray's now-removed HTML status page template used to do with `{{ if not .Status.LastHandshakeAt.IsZero }}`.
12. **Runtime State Persistence (`LastHandshakeAt`)**: `Runner.lastDrain.LastHandshakeAt` is persisted to a per-platform runtime state file (`internal/runtime`, sibling to `agent.log` in the XDG-state dir) on every successful drain pass and re-seeded at tray startup, so the Wails window's "Last successful handshake" row survives a tray restart (issue #149 / audit F-13 cross-session half). The seed sets `HandshakeOK=false` -- the seeded stamp is from a *prior session's* successful handshake, and `Status().HandshakeOK` is the *current session's* "last drain: handshake OK" signal; a pre-seed `HandshakeOK=true` would briefly lie about the current session before the drain timer's first tick. Write failures are non-blocking (`slog.Warn`, callback return value is swallowed) and panicking callbacks are recovered -- a failing `os.WriteFile` must never block a drain pass. The runtime state file is distinct from `config.yaml` (operator-edited, never agent-written). File durability: the state file is created at 0o600 and its parent directory at 0o700, with a chmod-after-MkdirAll that retightens any pre-existing 0o755 dir; the atomic temp+rename write is followed by an fsync of the parent directory (POSIX `syscall.Fsync` on Linux/BSD, `fcntl(F_FULLFSYNC)` on macOS, no-op on Windows -- NTFS commits dir entries transactionally); chmod/fsync failures are logged at WARN and non-fatal; WriteFile/Rename failures return to the caller, which logs and continues so the drain pass never blocks on the freshness signal.
13. **Ingest Core Has No UI Imports**: `internal/ingest` is intentionally UI-free -- no `fyne.io/systray`, no platform-windowing deps -- so the same headless engine can be driven by `cmd/branchdam-agent/ingest` (M1's headless half) and `internal/tray` (M1's tray-resident shell), and so cross-compile properties for `internal/ingest` are unaffected by the tray's `windows/darwin` build-tag split. The tray package is a thin driver over the engine, not a reimplementation (see `internal/tray`'s package doc).
14. **Detector lifecycle (#78)**: `Runner.ReconfigureDetector` cancels the in-flight `Detector.Watch` via a stored `detectorCancel` + `detectorDone` (guarded by `detectorMu`) and starts a new goroutine when `cardRoots` changes; an empty `roots` slice early-returns without starting a new one (`tray.go:1297-1299`), which is the stop-the-detector path -- except where `ingest.RemovableDriveDetection` is true (Windows), whose detector also polls removable drives (`GetLogicalDrives` + `GetDriveType == DRIVE_REMOVABLE`, `ingest.ListCardVolumes`) and so runs with no `cardRoots` at all. Replaces the "process restart" path. A settings reload never restarts the detector directly: a detection-triggered ingest runs on the detector's context, so a restart would cancel it. `SetDetectorInterval`/`SetDetectorRequireDCIM` only record the new `ingest.pollIntervalSecs`/`ingest.requireDCIM`, and the reload's `Runner.Reconfigure` restarts the detector (roots changed, or `detectorStale`) once it is applied -- after the gate frees, never under an ingest (invariant 9). "Ingest now" and the resume offer read the new `requireDCIM` at once. (`internal/tray/tray.go` `ReconfigureDetector`, `applyPendingReconfigAndUnlock`)
15. **Tray pause gates (#83 + #84)**: Two independent gates guard the network side. `paused` (atomic.Bool, **session-only — never persisted**; toggled from the tray menu or the window's Pause/Resume via `POST /api/actions/pause`, and also refused up front by `POST /api/actions/ingest-start`) short-circuits `TriggerIngest` / `TriggerDrain` / `TriggerPrune` and holds detector insertions (`Runner.pausedInserts`) instead of ingesting them, but never cancels an in-flight ingest. Resuming offers every held volume that is still present through `TriggerDetectedIngest` (skip set + `IngestGate`, same as a live detection) on its own goroutine; a card removed mid-pause is forgotten, and one handled before the pause is not re-offered -- a detector restarted by a reload starts from the volumes the old one reported, whatever their ingest outcome (`Detector.Known`, `Runner.detectedVolumes`; re-insert or "Ingest now" to offer one again), and a detection that reaches `triggerIngest` while paused is held, never dropped. `pauseUploadOnMetered` (a persisted `ingest.pauseUploadOnMetered` config key, edited via the Settings menu, **survives restarts**) + `netgate.IsMetered()` true short-circuits `TriggerDrain` only — local edit copy proceeds regardless. (Separately, the ingest engine's upload mode reads the same key per file and reports the upload `Deferred`, keeping the verified local copy; deferred uploads are not queued -- see `docs/offline-queue.md`.) The drain gate's `metered || mErr != nil` short-circuit in `TriggerDrain` (a synchronous probe on the drain goroutine, never a cached value) is the fail-closed guarantee at the call site; `netgate.IsMetered` itself is best-effort (e.g. `netgate_linux.go`'s `checkSysfsWWAN` returns `(false, nil)` on its own `ReadDir` failure). The tray menu loop never calls the probe: `Status().UploadPausedMetered` (tooltip display only) reads a cache refreshed off-loop (`internal/tray/metered.go`, 30s TTL, a probe error shown as metered; a probe in flight past `meteredProbeStall` is shown as metered and replaced, its late answer discarded). (`internal/tray/tray.go`, `internal/tray/metered.go`; `internal/netgate/`)
16. **Content dedup on in-flight hashes, with offline-aware fail-open (#88 + #82)**: `checkContentDedup` runs against `GET /api/v1/agent/check-content` in both `IngestCard` (online) and `IngestCardOffline`, *after* `DualWrite`/`WriteLocal` and before `Verify`, on the hashes the copy computed in flight -- it never reads the card itself (invariant 1). Phase 1 is the fast pre-screen (`fastHash` + `sizeBytes`, no `fullHash`); only on `possibleMatch: true` does phase 2 send `fullHash`. A confirmed match in a live state (`ACTIVE` or `HIDDEN`) is a duplicate: online removes the two copies `DualWrite` itself just created (O_EXCL, so they are its own), offline returns before the queue row so only its temp copy is removed; neither registers anything nor writes a queue row (online dedup runs before `registerNode`). A match at this file's own archive container path is the copy just written, never a duplicate. A re-run's already-present copies (`confirmRegistered`, invariant 3) share the pass's `dedupState` but skip the pre-screen -- the local copy's hash is in hand -- and look up `fullHash` directly (with `fastHash` + `sizeBytes`; a 400 retries once as `fastHash` + `fullHash` and sets `fullOnly`); there a live node at the own container path is evidence of registration (skip), and a pre-existing copy is never deleted. Each request has a per-file timeout (`PreflightTimeoutSecs`, 5s online / 2s offline) and every failure falls open. Per-pass `dedupState`: `unavailable` latches on a transport error, 404/501 (no endpoint), 401/403 (key refused) or 429 and skips the check for the rest of the pass; a 400 on the pre-screen means a server predating it, so `fullOnly` sends the rest of the pass straight to the full-hash lookup (dedup keeps working) -- a 400 never latches `unavailable`. The failure that latches is logged at WARN (later files skip the check quietly). Both reset per pass/card. There is no run-level probe. Upload mode (`ingest.uploadStream`) runs no `checkContentDedup`: its upload carries the in-flight BLAKE3 in `X-Blake3-Hash`, and the server answers a file it already holds live with `200 DEDUPLICATED` without receiving it -- the same after-copy, in-flight-hash rule, applied server-side. The offline auto-fallback in `TriggerIngest` (NAS unreachable → `IngestCardOffline` instead of error) is gated on `queueReader != nil`. (`internal/ingest/ingest.go` `checkContentDedup`/`dedupState`, `offline.go` `ingestFileOffline` step 4)
17. **M5 tray UX wiring (#79 + #80 + #81 + #86 + #87)**: Five tray behaviors wired through Settings submenus and the headless `ingest` subcommand's `-allowed-extensions` override: (a) `IngestGate` confirmation dialog wrapping the detector's `triggerIngest(..., isDetection=true)` (tray.go:478-502) with an `autoImportPaths` allow-list; manual `TriggerIngest` (incl. "Import from folder…", run_supported.go:385) bypasses it. A dialog-render error is NOT added to the skip set (only explicit refusals are). (b) "Import from folder…" manual source picker reusing the same `dialogRunner`. (c) `RequireDCIM` (volume filter at `ListVolumesUnder`, applied by both the detector and "Ingest now", which ingests each `selectCardVolumes` entry -- never a `cardRoots` parent -- and drops any volume containing or inside the archive/local edit root, `internal/tray/cardscope.go`) + `AllowedExtensions` (walk-time filter at `shouldSkipByExtension`, ingest.go:235 / offline.go:128); empty `allowedExtensions` = "accept all" (backward-compat). (d) `PathTemplate` overwritten by `Handshake.NamingTemplate` at tray startup and on every `reload()` — operator edits survive only between Handshakes. (e) `autoEject` only fires for a detection-triggered ingest of exactly a card volume root (`shouldAutoEject`; manual ingests -- "Ingest now", "Import from folder…", `/api/actions/ingest` -- never eject; the headless `ingest -card` subcommand ejects only when `tray.IsCardVolumeRoot` holds for its path) whose summary is `OK()` (false while any upload is `Deferred` on a metered connection), via the platform-tagged `internal/eject` package (Linux: `udisksctl unmount -b <dev>` then `udisksctl power-off -b <dev>`; Darwin: `diskutil unmountDisk`; Windows: `FSCTL_LOCK_VOLUME` (retried) -> `FSCTL_DISMOUNT_VOLUME` -> `IOCTL_STORAGE_MEDIA_REMOVAL` (allow) -> `IOCTL_STORAGE_EJECT_MEDIA` via `DeviceIoControl`, stopping at the first failed step with an `eject.StepError`, and a removable drive root (`E:\`) counts as a card volume root; other: `ErrUnsupported` stub).

## Review thread resolution

Hermes reviews automatically on open (`.github/workflows/hermes.yml`'s
`auto-review` job) — don't also `@s3ntin3l8-hermes Review` right after
opening the PR, or you'll trigger a redundant second review. A re-review
can be requested the same way after pushing fixes, but keep it to a
couple of rounds — don't loop on it indefinitely.

Every review thread (Hermes or human) must be replied to and resolved before
a PR is mergeable. This is a GraphQL-only concept, not a `gh pr` verb:

```sh
# 1. Reply to inline comment (REST)
gh api repos/s3ntin3l8/branchdam-agent/pulls/<PR>/comments/<comment_id>/replies -f body="Fixed in <sha>"
# 2. Resolve thread (GraphQL)
gh api graphql -f query="mutation { resolveReviewThread(input: {threadId: \"<thread_id>\"}) { thread { isResolved } } }"
```
